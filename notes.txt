install.sh notes
================

Claude Code's config is not tracked (decided 2026-09-20), and AI/.config/opencode
carries only opencode.json and tui.json. rtk's and icm's generated files (RTK.md,
CLAUDE.md, commands, plugins/{icm,rtk}.ts, settings.json hooks) are regenerated by
each tool's own init command, tied to the machine's binary paths and version, so
dotfiling a frozen copy would go stale and conflict with the real thing.

bootstrap/install.sh runs these steps. Notes on each:

  rtk init --global --opencode --auto-patch
                                     # writes RTK.md and an @RTK.md line in
                                     # CLAUDE.md, patches the settings.json hook,
                                     # installs the OpenCode plugin
                                     # (plugins/rtk.ts). No login needed, but
                                     # ~/.claude must already exist (mkdir -p it)
                                     # or it exits 1. Tested 2026-09-20 in a
                                     # throwaway HOME.

  icm init                          # standard mode: CLAUDE.md instructions +
                                     # /recall + /remember commands + hooks, for
                                     # both Claude Code and OpenCode
                                     # (plugins/icm.ts, skills/icm-*). No login
                                     # needed, but it finds the agents by BINARY on
                                     # PATH (an empty ~/.claude does not count).
                                     # Without `claude`/`opencode` on PATH it
                                     # exits 0 and silently configures nothing, so
                                     # install the agent CLIs first and put
                                     # ~/.local/bin and ~/.opencode/bin on PATH.

  wt config shell install           # worktrunk IS installed — binary is
                                     # named `wt`, not `worktrunk` (that's
                                     # just the project/config-dir name).
                                     # This is the actual init step: without
                                     # it, `wt switch` can't cd for you.
                                     # config.toml itself is user-authored
                                     # (worktree-path template, LLM commit
                                     # command) — already a normal dotfile
                                     # at .config/worktrunk/config.toml, no
                                     # generation step needed for it. Already
                                     # correctly stowed (directory-level
                                     # symlink, ~/.config/worktrunk ->
                                     # ../dotfiles/.config/worktrunk since
                                     # commit 67a7292) — an earlier note here
                                     # wrongly claimed otherwise.
                                     # Run it AFTER stow: with the stowed .zshrc it
                                     # is a no-op (dry-run checked 2026-09-20), so
                                     # it can't dirty the repo. Use `zsh` only.

  wt config plugins claude install  # worktrunk's Claude Code plugin
                                     # (activity tracking + statusline,
                                     # /worktrunk + /wt-switch-create skills).
                                     # NOT currently installed on this machine
                                     # (checked: no worktrunk marketplace, no
                                     # skill files anywhere) — so nothing to
                                     # exclude from dotfiles yet, just don't
                                     # dotfile whatever it drops once it is
                                     # installed, same reasoning as the rtk/icm files.
                                     # Manual alt: claude plugin marketplace
                                     # add max-sixty/worktrunk && claude
                                     # plugin install worktrunk@worktrunk -y

  wt config plugins opencode install  # OpenCode counterpart — writes
                                     # ~/.config/opencode/plugins/worktrunk.ts
                                     # (activity tracking only; OpenCode can't
                                     # do the worktree-isolation part). Also
                                     # not installed yet. Once it is: don't
                                     # dotfile worktrunk.ts, same as icm.ts/
                                     # rtk.ts above —
                                     # rerun this command instead.

  # --- toolchains ---
  curl -fsSL https://bun.sh/install | bash          # bun (1.4.0 currently)

  curl -fsSL https://get.pnpm.io/install.sh | sh -  # pnpm (11.10.0 currently)
                                     # this is what wrote the PNPM_HOME
                                     # block in .zshrc — reinstalling should
                                     # reuse it, not duplicate it

  # nvm: DECIDED 2026-09-20. Node comes from nvm on every machine (brew is
  # heavy or absent on a VPS, so it can't be the common path). In this order:
  PROFILE=/dev/null bash -c "$(curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/HEAD/install.sh)"
                                     # PROFILE=/dev/null stops the installer
                                     # appending its own block to ~/.zshrc. That
                                     # file is stowed from this repo and already
                                     # has an NVM block inside the awesome-lazy-zsh
                                     # managed block, plus an NVM_BIN line after the
                                     # block that puts nvm's node first (`brew shellenv`
                                     # prepends /opt/homebrew/bin, so brew's node would
                                     # win otherwise).
  ln -sf ~/dotfiles/bootstrap/npm.txt ~/.nvm/default-packages
                                     # nvm installs everything in this file after
                                     # each `nvm install`, skipping # and blank
                                     # lines. That replaces the per-package
                                     # `npm install -g` loop, and keeps globals
                                     # in step across node versions. Must come
                                     # AFTER the installer: it git-clones into
                                     # ~/.nvm and fails if the dir is non-empty.
  nvm install --lts && nvm alias default 'lts/*'
                                     # Brew's own node stays installed, as a
                                     # dependency of agent-browser, typescript,
                                     # typescript-language-server and
                                     # awesome-lazy-zsh. Harmless while the NVM
                                     # block stays after `brew shellenv`.
                                     # Checked 2026-09-20: the `# Pi` PATH line in
                                     # .zshrc is dead. It hardcodes vite-plus node
                                     # 24.19.0, whose bin has no `pi`, and
                                     # ~/.vite-plus/bin/pi is a dangling symlink
                                     # into it. The working `pi` is brew-node's
                                     # global, /opt/homebrew/bin/pi. Should be
                                     # safe to delete that line. ~/.vite-plus/env
                                     # also puts vp's node/npm shims on PATH; nvm
                                     # shadows them while its block stays last.

install.sh as built (2026-09-20). Steps run in this order; --skip NAME skips one.
================================================================================

  preflight       OS, not root, sudo, git
  prerequisites   Mac: Xcode command line tools, Homebrew. Ubuntu: bootstrap/apt.txt, Linuxbrew
  brew            brew bundle --no-upgrade: Brewfile, then Brewfile.mac on a Mac
  toolchains      bun, pnpm, nvm v0.40.7 (default-packages -> npm.txt, nvm install --lts)
  agents          Claude Code and opencode from the vendors' installers, skipped if present
  globals         bun.txt, pnpm.txt (npm.txt arrives through nvm default-packages)
  omz             oh-my-zsh clone + omz-plugins.txt
  stow            real ~/.config and ~/.config/opencode, back up conflicts, stow . AI
  linux           Ubuntu only, UNTESTED: /opt/homebrew symlink, iterm2 stub
  inits           mkdir ~/.claude; rtk init; icm init; wt config shell install zsh
  finish          chsh to zsh (Ubuntu), repo-dirty warning, the manual checklist

  Flags: --dry-run, --upgrade, --check-cleanup (prints, never removes), --skip NAME.
  Re-runs only add what is missing. Claude Code's settings.json is not managed;
  opencode.json and tui.json are stowed from AI/.

Why this order
  - toolchains and agents run BEFORE stow: bun's and pnpm's installers append to
    ~/.zshrc with no opt-out, and Claude's installer sets up "shell integration".
    ~/.zshrc is stowed from the repo, so after stow they would edit the repo. Before
    stow the edits land in a file stow then backs up. (opencode has
    --no-modify-path, nvm has PROFILE=/dev/null.)
  - a real ~/.config/opencode BEFORE stow: otherwise stow folds it into the repo and
    rtk/icm write plugins/ and skills/ into it (tested in a throwaway HOME).
  - inits AFTER the agent CLIs: icm finds agents by binary on PATH.

Facts found while building it (stow 2.4.1)
  - conflicts are reported as "cannot stow <src> over existing target <path> since
    neither a link nor a directory". They are moved to ~/.dotfiles-backup/<timestamp>/;
    never --adopt.
  - command-line --ignore is matched against the whole relative path, unanchored at
    the start, and ^/path forms are silently ignored. Top-level names use ^name$,
    nested ones a plain suffix (ghostty, sketchybar, \.aerospace\.toml). Verified.
  - a symlink in stow's way that stow does not own is a hard stow error, not a
    conflict, so the step reports it and fails.
  - installers are downloaded to a temp file and then run; `curl | bash` reports
    success on a failed download.

Tested on the Mac: syntax under bash 3.2, shellcheck, --dry-run, and the conflict
backup + stow in a throwaway HOME (files moved, links made, second run a no-op).
NOT tested: the whole Ubuntu path (apt, Linuxbrew, the /opt/homebrew symlink, the
iterm2 stub, chsh, the vendor installers on Linux) and a first run on a machine with
nothing installed. Run --dry-run first on the VPS.

Linux/VPS (Ubuntu) requirements found by the 2026-09-20 config audit
=====================================================================

  sudo apt-get install -y build-essential curl git procps file zsh unzip ca-certificates
                                     # Linuxbrew prerequisites, zsh for chsh,
                                     # unzip for nvim's Mason installs.
  Linuxbrew itself: the official installer, as a normal user with sudo. Default
  prefix /home/linuxbrew/.linuxbrew, so bottles are used instead of source builds.

  sudo ln -s /home/linuxbrew/.linuxbrew /opt/homebrew      # UNTESTED
                                     # .zshrc's awesome-lazy-zsh managed block
                                     # is regenerated by the tool, so it can't be
                                     # edited, and it hardcodes /opt/homebrew:
                                     # `brew shellenv` and the alias files it
                                     # sources. The symlink makes those resolve
                                     # on Linux. Try it in an Ubuntu container
                                     # first.

  touch ~/.iterm2_shell_integration.zsh     # Linux only: the managed block sources
                                     # it unguarded and would print an error.

  stow --ignore for Linux/VPS: Library, .wezterm.lua, .config/ghostty,
  .config/sketchybar, .config/.aerospace.toml (all Mac-only), plus
  vira-theme-for-terminals if the clutter matters. The ignore args are regexes.

  Install sources for the tools that had none (decided 2026-09-20):
    atuin       brew "atuin" in Brewfile (was a curl installer into ~/.atuin).
    mise        brew "mise" in Brewfile.mac; it only manages tuist, for ~/Projects/Cork.
    oh-my-zsh   git clone --depth=1 https://github.com/ohmyzsh/ohmyzsh.git ~/.oh-my-zsh
                A plain clone, not its installer: the installer replaces ~/.zshrc
                unless KEEP_ZSHRC=yes, and that file is stowed from this repo.
    omz custom plugins
                bootstrap/omz-plugins.txt, one `name url` per line, cloned into
                ~/.oh-my-zsh/custom/plugins/<name>. awesome-lazy-zsh has no install
                command (only update, --add-plugin, --doctor), so the script clones
                them. The Mac also has custom/plugins/{thefuck,z,you-should-use}, but
                those do nothing: omz loads a custom plugin only when its dir holds
                <name>.plugin.zsh, so `thefuck` and `z` fall back to omz's built-ins,
                and you-should-use isn't in plugins=().
    check       `awesome-lazy-zsh --doctor` (looks for node, zsh, git).
    removed     openclaw and workmux: configs, .zshrc lines and notes deleted.
